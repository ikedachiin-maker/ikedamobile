# 決済×データ管理×自動通知 システム構築スキルテンプレート

イケダモバイルの構築経験をもとに、同様のシステムを横展開する際の再利用可能なスキルセットと手順をまとめる。

---

## 対象となるビジネス例

- 格安SIM販売（イケダモバイル）
- コンサルティング申し込み
- オンラインスクール入会
- イベント参加申し込み
- サブスクリプションサービス

**共通点**: お客様が申し込み → 決済 → 運営側で処理 → 結果を通知

## 技術スタック（推奨構成）

| レイヤー | 技術 | 選定理由 |
|----------|------|----------|
| 言語 | Python 3.10+ | Google API・Stripe SDK・Seleniumとの親和性が高い |
| Webフレームワーク | Flask | 軽量・学習コスト低・小〜中規模に最適 |
| 決済 | Stripe | 導入が簡単・手数料3.6%・API/Webhookが充実 |
| データ管理 | Google Spreadsheets（gspread） | 非エンジニアでもデータ確認可能・無料 |
| ファイル保存 | Google Drive API | 本人確認書類などのファイル管理 |
| メール送信 | Gmail API | 無料・到達率が高い・Googleアカウントで完結 |
| ホスティング | Railway | GitHub連携デプロイ・月$5〜・SSL自動 |
| DNS | Cloudflare | 無料・高速・DDoS保護 |
| ブラウザ自動操作 | Selenium + Chrome | APIがない外部システムとの連携 |
| 定時実行 | cron（Mac）/ Railway Cron | 毎日の定期バッチ処理 |

## 注意事項・ノウハウ

### 認証まわり

- Google OAuth の token.json は有効期限がある（約7日で refresh が必要）
- Railway では credentials.json / token.json をファイルで置けないため、環境変数にJSON文字列として格納する
- スコープは最初に全て指定しておく（後から追加すると token.json の再生成が必要）

### Stripe

- 本番切り替え時は `sk_test_` → `sk_live_` / `pk_test_` → `pk_live_` の変更を忘れない
- Webhook の署名検証は本番では必須（テスト時はスキップ可）
- Stripe ダッシュボードで Webhook URL を本番ドメインに変更する

### Railway

- Root Directory はリポジトリ構成に合わせて正しく設定する
- `PORT` 環境変数は Railway が自動設定するため、コード側で `$PORT` を参照する
- GitHub push で自動デプロイされる

### Selenium

- Railway 等のクラウド環境では Chrome が動かない場合がある
- ヘッドレスモード必須（`--headless`）
- 対象サイトのUI変更で壊れるリスクがある → 定期的な動作確認が必要
